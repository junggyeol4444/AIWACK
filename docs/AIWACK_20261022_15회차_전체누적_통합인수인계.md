### 실제 개발 A — 총괄 GGUF 15부서 5개 묶음의 SQLite 영속 복구
- `windows-integrated-src/desktop/company_wide_campaign.py`에 `aiwack_wide_chief_group_staging` 저장소·불변 트리거·SHA256·모델 호출 감사 검증 추가. 총괄이 생성한 3부서 그룹 1개를 실제 성공 모델 호출 및 부서 목록과 결합해 원자적으로 저장한다.
- 그룹 2~5에서 실제 모델 응답 실패/취소/프로세스 종료가 발생해도 이전 성공 그룹의 실제 지시·호출 ID를 보존한다. 다음 실행은 같은 원본 업무·31명 조직·모델·실제 호출 감사가 모두 일치할 때만 저장된 그룹을 재사용한다. 다른 업무·모델·직원 구성, 변조된 계획/호출 감사는 거부한다.
- 3부서 동시 계획 실패 시 기존 실제 단일 부서 재호출 3건의 각 모델 호출을 별도로 감사하고 그룹으로 저장한다. 빈 모델 응답을 합성 작업으로 대체하지 않는다. 5개 그룹 검증이 모두 끝난 뒤에만 기존 30개 초안을 만들고, 30개 업무 생성·실행에는 기존 별도 관리자 승인이 필요하다.

### 실제 개발 B — 기존 Windows 한글 Tk GUI/SQLite API/실GGUF 검증 연결
- `windows-integrated-src/desktop/storage.py`: 기존 LocalStore에 `staged_full_company_progress` 조회 연결.
- `windows-integrated-src/desktop/app.py`: 기존 15부서·31명 탭에 `총괄 계획 중단·재개 상태` 버튼 추가. 0/5~5/5 실제 모델 계획 그룹 저장 진행도를 표시하고 동일 기준 업무 재실행 시 남은 그룹부터 진행함을 안내. 새 앱/WebUI는 만들지 않음.
- `validation/windows_real_30_step_campaign_e2e.py`: 실패 체크포인트에 저장된 그룹 번호·SHA256 감사 메타데이터를 추가. `--resume` 시 기존 31명/모델/원본 업무와 그룹의 실제 호출 감사를 확인한 후 재개하도록 연결. 외부 실거래나 임의 관리자 승인은 실행하지 않음.
