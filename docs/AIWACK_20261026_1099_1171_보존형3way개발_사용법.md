# AIWACK 1,099개 원본·1,171개 누적소스 보존형 3-way 병합 개발

대상: 기존 Windows 10/11 한국어 Tkinter·SQLite·실제 GGUF AIWACK GitHub 소스.

이 도구는 실제로 확보한 과거 A 원본 ZIP과 이후 B 누적 ZIP을 현재 main 소스 체크아웃과 3방향으로 대조하고 **원본을 덮어쓰지 않는 병합 후보**를 생성한다.

## 개발된 소스

preservation/safe_three_way_source_merge.py

- 원본 ZIP A와 누적 ZIP B의 항목·SHA256, 현재 체크아웃 개별 파일 SHA256을 비교한다.
- ZIP 절대경로·상위 폴더 이동·중복 경로·Windows 파일명 대소문자 충돌·심볼릭 링크·8MiB 초과 파일을 거부한다.
- A→B 수정과 A→현재 main 수정이 서로 겹치지 않는 **텍스트 라인 구간**인 경우에만 자동 병합 **후보**를 생성한다.
- 동일 줄에서 서로 다르게 변경된 경우 모든 원문(base/later/main)을 별도 conflicts 폴더에 보존하여 승인 없는 선택/덮어쓰기를 차단한다.
- 과거 ZIP B에만 존재하고 현재 main에 없는 기록은 staged 폴더로 별도 보존한다.
- 기존 개인용 dev_company.sqlite3 등의 DB·개인키 파일을 추출하거나 현재 사용자 SQLite를 변경하지 않는다.
- 대상 checkout 바깥의 신규 stage 폴더만 허용하고, 기존 stage 이름에 덮어쓰지 않는다.
- MANIFEST.json에 파일별 해시·사유·후보/충돌 경로를 적는다.

## 실행 형태 (개발 도구, Windows EXE 통합검증 아님)

Windows PowerShell에서 로컬 Python 환경이 이미 있을 때:

    python preservation\safe_three_way_source_merge.py --original C:\AIWACK_archives\original_1099.zip --cumulative C:\AIWACK_archives\cumulative_1171.zip --main-checkout C:\AIWACK_repo --stage C:\AIWACK_three_way_stage

이는 예시 경로일 뿐 실제 원본 ZIP 파일명은 사용자가 보유한 것으로 지정한다. **원본 프로젝트 경로와 사용자 DB를 덮어쓰지 않는다.** 별도 stage 내 staged 후보와 conflicts 사본을 조사한 뒤, 합의된 개별 파일만 향후 main에 보존형 병합할 수 있다. 이 실행 명령은 이번 개발 회차에서 실제로 수행하지 않았다.

## 확인하지 않은 항목

- 역사 변경 52개 파일이 모두 자동 병합되었다는 주장은 하지 않는다.
- 누락된 역사 원본 28개가 GitHub main에 원문으로 복원되었다는 주장은 하지 않는다.
- 실제 Windows 10/11 EXE·31개 GGUF 모델·T01~T20·24시간 운영 통합검증은 NOT_RUN.
- 사용자 지시: 모든 개발 및 원본 보존형 병합 → 전체 통합검증 → 오류 일괄 수정 → 전체 재검증.
