## 이번 실제 개발 (11회차 전체 소스 위에 누적)
1. desktop/company_wide_campaign.py: 3부서 실제 총괄 응답에서 요청하지 않은 부서가 추가되면 무시하고 통과시키던 경로를 거부. Markdown 표 헤더/구분자는 정상 제외. 단일 부서 fallback에서 다른 부서명을 생성한 응답을 잘못 해당 부서 계획으로 취급하던 경로를 차단. 진짜 생성 결과만 사용하고 합성 계획 생성하지 않음.
2. desktop/company_wide_campaign.py: 승인된 직원 결과물과 총괄 보고서의 실제 모델 호출 ID/직원/성공 상태/호출 순서를 SQLite에서 별도로 대조하는 읽기 전용 지표 `verified_chief_model_call_links`, `all_30_chief_model_call_links_verified` 추가. 기존 구조적 30단계 승인 수와 실제 호출 감사 수를 혼동하지 않음. 이 지표도 GGUF 바이너리의 독립 검증은 아니므로 `actual_gguf_binary_verified=False` 유지.
3. desktop/company_customer_cases.py: 고객지원 승인 답변에 총괄 실제 호출 감사가 연결됐는지 `chief_model_call_audited`로 표시하고, 실제 고객 발송/PG/실GGUF 검증과 구분. 기존 승인/SQLite 감사/로컬 Markdown 파일 보존.
4. validation/windows_packaged_real_gguf_queue_e2e.py: 창 좌표 검증과 활성 창 재확인 뒤에도 HWND가 파괴되는 Windows 1400 경합을 줄이기 위해 클릭 직전 Win32 IsWindow/GetForegroundWindow 재확인. 64비트 HWND 포인터 인자형 명시. 파괴되었거나 포커스가 다른 경우 물리 클릭을 보내지 않음.
5. tests/test_round12_genuine_audit_and_fail_closed.py: 새 회귀 4건 추가(비요청 부서 차단, 총괄 감사 ID 변조 감지, 단일 부서 불일치 거부, 고객지원 실제 파일·재로그인·허위 실GGUF/발송 주장 차단). .github/workflows/ci.yml 기존 네이티브 테스트 목록에 연결.
