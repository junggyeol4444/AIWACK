1. `windows-integrated-src/desktop/company_wide_campaign.py`
   - 기존 총괄 실GGUF 3부서 파서에 JSON 배열/부서별 객체로 출력된 실제 생성 응답도 동일한 부서명·제목·지시 필드로 읽는 경로 추가.
   - 세 부서 이름의 정확한 일치, 제목/지시 길이, 빈 필드/없는 부서/상충 중복 계획 거부 유지. 모델이 생성하지 않은 계획 합성·관리자 승인 우회 없음.
   - 기존 5그룹×3부서·30역할·실모델 재호출 및 SQLite 감사 유지.
2. `validation/windows_real_30_step_campaign_e2e.py`
   - `--resume` 체크포인트에서 이전 직원 모델 호출 ID가 **바로 그 업무의 실제 실행 행 `company_task_runs.model_call_id`** 와 연결돼 있는지 검증. 같은 직원의 다른 성공 호출로 바꿔치기 불가.
   - 직원 결과물과 총괄 보고서의 저장된 본문 SHA256을 재계산하고 실제 승인 상태 확인. 체크포인트 성공 표식과 업무 수 불일치 거부.
   - 체크포인트를 임시 파일 fsync 후 원자적 `os.replace`로 저장, 기록 도중 종료돼도 기존 JSON 보존.
   - 이전 실패한 실GGUF 재시도가 존재해도 모든 직원에게 실제 성공 호출이 있는지 기준으로 최종 검증하고 실패 호출 수는 별도 보고. 실패를 성공으로 변경하거나 합성하지 않음.
3. `windows-integrated-src/tests/test_round9_genuine_campaign_recovery.py`
   - 신규 회귀 3건: 실제 출력 JSON 형식·누락/없는 부서 거부, 다른 성공 모델 호출/변조된 결과물로 재개 거부, 체크포인트 쓰기 오류 후 원문 보존.
