## 이번 실제 개발 (10회차 전체 누적 ZIP을 기반으로 변경)

A. 총괄 GGUF 실계획 처리: 기존 `windows-integrated-src/desktop/company_wide_campaign.py`의 생성 응답 파서를 확장하여 모델이 명시적으로 작성한 `plans`/`tasks` JSON 및 JSON 앞 짧은 설명을 처리한다. 지정된 세 부서 전부의 실제 제목·지시가 있어야만 승인 후보가 된다. 없는 부서, 누락된 부서, 불완전한 JSON, 생성되지 않은 지시를 합성하지 않는다.

B. 총괄 계획 원본 무결성·승인: `aiwack_wide_campaign_steps.plan_sha256`을 기존 SQLite 테이블에 추가하는 비파괴 마이그레이션과 초안 필드 변경 금지 트리거 구현. 생성 시 부서·직원·역할·제목·지시·실모델 호출 ID를 결합해 SHA256 기록. 관리자 승인 전 동일 내용·봉인 확인, 미승인 초안의 `task_id` 선삽입 탐지 후 30개 업무 생성 전체 거부. 기존 승인 기록은 삭제하지 않으며, 봉인이 없는 오래된 초안은 자동 승인하지 않는다. 기존 테스트가 이전 '승인 시 차단'을 기대하던 부분은 '변조 UPDATE 단계에서 즉시 차단'으로 갱신.

C. 실제 Windows GGUF 30업무 중단 재개: `validation/windows_real_30_step_campaign_e2e.py`의 `--resume` 사전 무결성 검사 실패 시 원본 체크포인트를 덮어쓰지 않고, 별도 `resume_rejected_*.json` 파일에 실패 종류와 원본 SHA256을 원자적으로 기록한다. 재개 사전 검증 성공 후에만 정상 체크포인트 갱신을 허용한다. 임의 재실행·가짜 호출·자동 승인 추가 없음.

D. Windows Tk EXE 물리 클릭 안전성: `validation/windows_packaged_real_gguf_queue_e2e.py`의 창 포커스 복구 중 검증되지 않은 타이틀바 좌표를 먼저 클릭하던 동작 제거. Win32 HWND 1400/포커스 경합 시 네이티브 창 활성화 재시도 후 불확실하면 마우스 입력 없이 중단. 물리 Windows 성공 주장은 아님.

E. 테스트·CI 연결: 신규 `windows-integrated-src/tests/test_round11_plan_seals_and_resume.py` 5개, `validation/test_windows_native_window_handles.py`에 포커스 경합 테스트 1개 추가. `.github/workflows/ci.yml`, `.github/workflows/windows-exe.yml`에 신규 구조 회귀 테스트 연결; CI에 Windows HWND 1400 순수 Python 검사 추가.
