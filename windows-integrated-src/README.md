# Stage61: 범용 사업 유형 관리 (오프라인 부분 구현)

원본 기획안 §4.2의 예시 사업 유형 14종 및 제한 없는 사용자 정의 사업 유형을 SQLite에 등록합니다.
한 유형에 여러 사업 계획을 만들고, 목표·계획 예산(실제 지출 아님)·기존 AI 직원 책임자/참여자·로컬 상태를 관리합니다.
관리자 Tkinter `범용 사업 유형·사업 관리` 탭에서 유형 등록, 사업 등록, 상태 변경, 참여 직원 등록/해제,
목록 확인이 가능합니다. 상태 `active`는 계획 상태일 뿐 실제 판매·배포·업무 실행을 시작하지 않습니다.
사업 변경 이력은 추가 전용 SQLite 기록과 SHA-256 일관성 확인을 지원하나 외부 변조 방지 보안 저장소는 아닙니다.

**61단계는 부분 구현/보류, 다음 개발 대상은 62단계입니다.** 원본 §4.3의 사업별 실제 업무·서비스 계정·
매출/지출/순이익·고객·평가 통합, 자동 사업 발굴 및 실제 수익 창출은 미구현입니다.
Windows 실기기/EXE, 실제 GGUF, 외부 서비스·장시간 운영은 미검증입니다.
완전 완료 54/100(1~53,55)는 현재 개발 순번과 다릅니다.
검증 기록: `docs/verification_stage61_business_portfolio/`.

**주의:** 아래의 54단계 중심 설명과 완료 수치는 과거 단계에서 작성된 이력입니다.

# 54단계 부분 구현 — 저장 HTML의 능동 요청 대상 사전 경고 (오프라인)

### 54단계 진행 중 — 로컬 자료 묶음 지문 기록의 생성 중 변경 방지 (2026-10-14)

관리자가 승인해 수행하는 기존 `묶음 파일 지문 JSON 저장` 동작을 강화했습니다.
목록과 최대 20개 원본 파일을 순차적으로 SHA-256 검사한 뒤, 지문 기록 JSON을
쓰기 직전에 목록 및 모든 원본 파일을 **다시 검사**합니다. 검사 사이 목록 변경,
앞서 검사한 파일의 변경·삭제가 확인되면 새 기록은 만들지 않고 재검토를 요구합니다.
이 검사는 파일시스템 전체의 원자적 스냅샷을 제공하지 않습니다. 마지막 검사
직후부터 저장 사이에 발생한 변경을 완전히 배제할 수는 없습니다.

SQLite 스키마·기존 자료·원본 기획서는 변경하지 않습니다. 외부 서버·DNS·GitHub
접속과 클라우드 API는 사용하지 않습니다. 실제 인터넷 자동 자료 수집이
미구현이므로 54단계는 **진행 중**이고, 1~53단계만 완료(53/100)입니다.
Windows 실기기·EXE·실제 모델·장시간 운영은 미검증이며, 제품 완성도 약 20~25%는 주관적 추정입니다.


로컬 조사 JSON 묶음의 등록 **승인 전** HTML 내 `form action`(GET/POST 메서드 표기 포함), `iframe src`, `script src`를 최대 8건/파일 문자열로 분석하여 동일 출처/다른 출처/형식 오류를 표시합니다. 실제 제출, HTML 실행, DNS/HTTP 통신 없음. 상위 4개 예시만 표시하며 정확한 브라우저 동작·보안성을 재현하거나 출처를 인증하지 않습니다. 이전 승인 토큰/원본 파일 변경 검사 및 소유자 승인을 유지합니다. 새 기능 및 검증 제한은 `docs/verification_stage54_active_targets/summary.md`를 확인하세요. 완료 53/100, 54 미완료, 제품 성숙도 약 20~25%(주관적 추정).

# 54단계 추가 부분 구현 — HTML 자체 출처 표기 사전 검토 (오프라인)

### Stage54 후속 개발 — HTML 폼 입력 유형 사전 경고 (54단계 미완료)

- 관리자 JSON 묶음 사전 검토에서 로컬 HTML의 **명시적 `<form>` 내부 `input type=password/file/hidden`** 유형만 정적으로 확인합니다. HTML 하나당 최대 8개, GUI 상세 예시 최대 4개를 기록합니다.
- 기본 GET 방식의 암호 입력은 별도로 주의 표시합니다. 입력 필드의 이름·값·암호·첨부 파일은 **검사 결과에 담거나 출력하지 않으며**, 폼 제출/스크립트 실행/외부 호출은 수행하지 않습니다. 등록은 이전과 동일하게 관리자 명시적 승인 후에만 가능합니다.
- 이는 **형식 문자열 기반의 제한적 사전 검토**입니다. HTML 밖에서 `form=` 속성으로 연결한 필드, JavaScript로 추가하는 필드, 숨김 값의 민감도, 실제 제출 성공 및 악성 여부는 판단하지 못합니다. 경고 미표시는 안전을 증명하지 않습니다.
- Windows 실기기·EXE 빌드·실제 GGUF·장시간 무인 실행은 미검증이고, **인터넷 자동 자료 수집은 미구현, 53/100 완료 및 54단계 진행 중**입니다. 검증 기록은 `docs/verification_stage54_form_controls/` 참고.

## Stage54 부분 구현: 묶음 등록 전 출처·버전 차이 경고 (오프라인)

Tkinter의 **자료 묶음(JSON) 가져오기**를 누르면 기존의 정확히 동일한 URL+본문
중복 차단 외에, 같은 **미검증 URL에 다른 본문**, 또는 서로 **다른 미검증 URL에
동일 본문**이 있는 경우를 사전 경고합니다. 기존/보관된 SQLite 자료와 묶음 내부를
비교해 사례 자료 ID 또는 묶음 순번을 표시합니다. 새 버전 등록은 차단하지 않고
관리자가 경고를 읽고 명시적으로 승인해야 진행됩니다. 사전 검토는 SELECT 전용이며
DNS·HTTP 접속은 없습니다. 동일 본문·해시는 웹 출처나 진위·독립성을 증명하지
않습니다. 54단계의 실제 인터넷 자동 자료 수집은 미완료입니다.
검증: `docs/verification_stage54_bundle_provenance/summary.md`.

## Stage54 계속 개발 — 로컬 묶음 JSON 목록 생성 도우미 (진행 중)

- 오프라인 조사 화면의 **로컬 묶음 JSON 목록 만들기** 버튼에서 관리자가 같은 폴더의 TXT/MD/HTML 파일 1~20개를 직접 선택하고, 각 자료의 **미검증 출처 URL과 제목**을 직접 입력합니다. 승인 후 **선택한 파일과 같은 폴더**에 `aiwack-offline-research-bundle-v1` 형식 JSON을 생성합니다. 기존 자료 묶음 사전 검토/승인 가져오기 기능과 연결됩니다.
- 입력 파일당 최대 256,000바이트, 목록 파일 최대 32,768바이트. 기존 출력 파일 덮어쓰기 금지, 로컬 경로만 허용, 심볼릭 링크/Windows 접합점/네트워크 드라이브를 거부하도록 구현했습니다. 로컬 원본 파일 바이트 해시를 확인하지만 원본 파일 내용은 출력 목록에 복제하지 않습니다.
- **목록 생성은 SQLite에 자료를 등록하지 않습니다.** 사용자가 별도 `자료 묶음(JSON) 가져오기`를 선택하여 사전 검토 후 승인해야 등록됩니다. 입력 URL은 사용자가 주장한 메타데이터로 출처 진위나 출판 시각을 보장하지 않습니다. 인터넷 접속·DNS 조회·AI 웹 자동 수집 없음.
- 완료 **53/100**, 54단계 **미완료**. 상세 검증 기록: `docs/verification_stage54_manifest_builder/summary.md`.

## Stage54 진행 중 — 로컬 자료 묶음 사전 검토 및 승인 후 가져오기

- `자료 묶음(JSON) 가져오기`를 누르면 사용자 지정 **로컬** JSON 목록과 최대 20개 텍스트·HTML 파일을 읽어 **사전 검토**합니다. 등록 전 파일명·크기·주장 URL·기존/묶음 내부 중복 건수를 화면에 표시합니다.
- SQLite의 이미 등록된 `(URL, 정규화된 본문 SHA-256)` 조합(보관 포함), 묶음 내부 중복을 검출하면 등록을 중단합니다. 동일 URL의 서로 다른 본문은 별도 버전 후보로 등록 가능합니다.
- 중복이 없으면 관리자에게 등록 여부를 묻고, 승인 시 **목록과 모든 로컬 파일을 다시 읽어 사전 검토 당시 해시와 비교**합니다. 변조나 파일 교체가 있으면 전부 롤백합니다. 승인 취소와 사전 검토만으로는 DB를 변경하지 않습니다. 원래의 SQLite 일괄 등록은 그대로 유지했습니다.
- 기술적 제한: 토큰은 동일성 판별용 무키 SHA-256이며 서명이나 권한증명이 아닙니다. 다른 프로세스의 동시 입력은 SQLite UNIQUE 제한으로 보호하지만 **사전 검토 이후 데이터가 다른 프로세스에서 등록될 수 있습니다**. 네트워크 출처의 진위/게시 시점은 확인하지 않습니다. 실시간 웹 접속, HTTP 요청, DNS 및 자동 수집 없음.
- 단계 1~53 완료, 54단계 **진행 중**. 검사 기록: `docs/verification_stage54_bundle_preview/summary.md`.

## Stage54 부분 개발: 로컬 조사 자료 중복·버전 차이 후보 점검 (0.1.53, 진행 중)

- 오프라인 조사 화면의 **자료 중복·버전 차이 점검** 버튼은 최신 최대 2,000개 저장 자료에서 ① 같은 본문 SHA-256을 가진 서로 다른 주장 URL, ② 같은 주장 URL에 서로 다른 본문 해시, ③ 같은 가져오기 당시 원본 파일 바이트 SHA-256을 가진 서로 다른 주장 URL을 찾습니다. 보관 자료 포함 여부를 선택할 수 있습니다.
- 종류별 전체 그룹 수, 그룹당 자료 수/서로 다른 값 수, 일부 자료 ID/주장 URL을 표시하며 상위 25개 그룹만 GUI에 표시합니다. 과거 자료가 2,000개 상한 밖이면 누락될 수 있습니다. 기존 데이터와 스키마는 변경하지 않습니다.
- **동일 해시/URL은 독립적인 웹 출처, 내용의 진실성 또는 실제 파일의 현재 상태를 인증하지 않습니다.** 파일을 다시 열거나 DNS/웹사이트를 조회하지 않습니다. 54단계 원격 자동 수집은 미구현이며 53/100단계 완료 상태를 유지합니다. 상세 테스트 기록: `docs/verification_stage54_source_overlap/summary.md`.

## Stage54 부분 개발: URL 경고 전체 JSON 저장·로컬 재검사 (0.1.53, 진행 중)

- **URL 경고 JSON 저장**은 관리자 승인으로 저장 HTML 링크 최대 2,000개 중 수동 필터(`all/pending/deferred`) 및 보관 범위에 해당하는 **경고 URL 전체**를 JSON으로 내보냅니다. GUI의 40개 표시 상한과 달리 전체 경고를 담습니다. URL, 경고 코드, 로컬 자료 후보 상태만 포함하고 수동 메모 본문은 내보내지 않습니다.
- **URL 경고 JSON 재검사**는 선택한 로컬 JSON의 SHA-256 자체 체크섬과 구조·분류 규칙을 검사하고, 저장 당시 필터로 현재 로컬 SQLite 자료를 다시 집계하여 추가·누락·변경된 경고 URL을 최대 20개씩 표시합니다. 관리자 로그인, 기존 파일 덮어쓰기 방지, 로컬 경로 제한, 읽기 전용 DB 비교를 적용합니다.
- **인터넷 접속·DNS 조회·URL 열기 없음.** 체크섬은 전자서명이 아니며, URL 경고가 없다고 접속 안전이나 출처 진위를 확인한 것이 아닙니다. 단계 1~53 완료, 54단계 진행 중. 테스트·한계: `docs/verification_stage54_preflight_exports/summary.md`.

## Stage54 후속 개발 — 로컬 조사 자료 묶음 일괄 가져오기 (아직 진행 중)

- 조회 상세에 묶음 정보가 나타나며 관리자의 로그인 권한이 필요합니다. 기존 조사 자료는 삭제·수정하지 않습니다. **원본 바이트는 DB에 저장되지 않습니다.** 목록 URL의 진위/게시 시점은 검증하지 않았습니다.

- 외부 서버 금지로 실제 인터넷 조사/검색/수집 미구현. **완료 53/100 유지; 54단계 진행 중**. 자세한 내용: `docs/STAGE54_BATCH_CONTINUATION_VERIFICATION.md`.

## Stage54 진행 중 (인터넷 조사 및 자료 수집 — 오프라인 사본 수집만 구현)

### Stage 51 — AI tool catalog (offline metadata only)

The administrator-only **AI 작업 도구 등록** Tkinter tab registers non-executable
local SQLite metadata: unique tool key, display name, category, description,
and an optional *declared* required employee capability. The tool catalog does

### 54단계 진행 중 — 오프라인 조사 자료 가져오기

관리자 로그인 후 `오프라인 조사 자료 수집` 탭에서 URL(출처 설명), 제목을 입력하고

자료를 **외부 접속 없이** 가져올 수 있습니다(256KB 제한). 문서 상세 화면에는 본문
SHA-256과 별도로 로컬 원본 파일 바이트의 SHA-256, 파일명, 크기, 가져온 날짜를
표시합니다. 원본 파일 자체는 SQLite에 보관하지 않습니다. 추출된 텍스트와
메타데이터만 보존합니다. URL이나 출처의 진위는 검증하지 않으며, 실시간 웹
수집·자동 검색은 구현되지 않았습니다. 따라서 54단계는 여전히 **진행 중**입니다.

### Stage54 부분 구현: 묶음 승인 사이 로컬 조사 자료 변화 감지

관리자가 JSON 자료 묶음을 사전 검토하고 등록을 승인하는 도중 다른 작업으로 관련
SQLite 조사 자료가 등록되면, **같은 주장 URL의 다른 본문** 또는 **같은 본문의 다른 URL**

**54단계 인터넷 조사·자동 자료 수집은 외부 서버 접속 금지로 미완료(BLOCKED)**입니다. 순차 개발을 중지하지 않고 55단계의 허용 범위에서 구현한 관리자 수동 브라우저 작업은 `desktop/offline_browser.py` 및 `desktop/app.py`의 **허용된 로컬 브라우저 작업** 탭에서 사용합니다. 관리자 본인이 HTML을 선택하여 내용을 읽고 문자열을 찾습니다. 설치된 Chromium/Chrome/Edge 및 Playwright가 필요하며, 자동 설치·다운로드하지 않습니다. 원본 HTML은 실행되지 않고 이스케이프한 평문만 브라우저에 전달됩니다. 네트워크/JS/외부 리소스는 브라우저 컨텍스트에서 차단하지만 OS 전체 통신 차단은 아닙니다. 원격 브라우저 자동화 기능은 없습니다.

완료: **54/100개 단계 (1~53 및 55)**; 보류: **54**; 다음 개발: **56**. 테스트 및 한계: `docs/verification_stage55_offline_browser/summary.md`.


## 56단계: 로컬 AI Python 코드 초안·수정 (**부분 구현 / 실제 모델 미검증**)

Tkinter의 **로컬 AI 코드 초안** 탭에서 관리자만 사전에 등록한 *로컬 CLI 모델* ID와 요청을 입력하여 Python 소스 초안을 만들 수 있습니다. 초안은 자동 저장되지 않으며, 관리자 구문 검사/통합 diff 미리보기, 별도 저장 승인을 거친 뒤 **데이터 폴더/code_drafts/** 내 단일 `.py` 파일에만 저장됩니다. 버전·SHA-256·코드 본문은 SQLite `local_code_artifacts` / `local_code_revisions`에 별도 기록됩니다. 기존 코드 버전 비교, 동시 변경 차단, 심볼릭 링크·하드링크·외부 파일 경로 차단을 적용합니다. 기존 AIWACK 프로젝트 코드를 수정하거나, 생성된 코드를 실행·테스트·설치하지 않습니다.

테스트에서는 로컬 모델 함수 응답을 **모의(mock)** 하여 초안 생성 흐름을 검증했습니다. **실제 GGUF 모델 추론, Python 코드의 보안/기능 정확성, Windows EXE는 미검증**입니다. 선택된 CLI 바이너리 자체가 네트워크를 사용하지 않는다는 OS 수준의 보증은 없습니다. 파일 쓰기와 SQLite 커밋을 완전히 원자적으로 묶을 수 없으므로 갑작스러운 전원 차단 시 확인이 필요합니다. **56단계는 BLOCKED(검증 보류)로 남기고 다음 개발 대상은 57단계**입니다. 54단계 인터넷 조사 또한 계속 BLOCKED입니다.

검증: `docs/verification_stage56_code_authoring/summary.md`. 완료 단계는 **54/100개 (1~53, 55)** 입니다.


## Stage57 제한형 코드 실행·테스트 (부분 구현, OS 격리 보류)

관리자 전용 **제한형 코드 테스트** 탭에서 Stage56에 승인 저장한 코드 ID와 1~20개 `assert` 조건을 입력하고 **별도 실행 승인** 후 검사합니다. AST 인터프리터는 Python 원본을 `exec`/`eval`/`compile`/import/외부 프로세스로 실행하지 않습니다. 단순 상수 대입, 함수, return, if, 제한된 사칙연산·비교, 사용자 정의 함수 호출만 허용합니다. 네트워크·파일·임의 라이브러리·루프·재귀·속성 접근·빌트인 함수 사용은 거부합니다. 노드/단계/값 크기·호출 깊이 상한을 적용합니다. 저장된 파일의 SHA-256/버전을 확인하며, 실행 결과(전체/통과 수와 코드·테스트 SHA-256, 상태)만 불변 SQLite 감사 이력에 기록합니다. 테스트 원문은 감사 로그에 저장하지 않습니다.

**이것은 임의 Python의 OS 격리 실행기가 아닙니다.** 관리자 세션 내부에서 제한형 AST를 해석하는 기능입니다. 운영체제 수준의 파일 시스템/네트워크 격리, 악성 네이티브 코드 실행 차단 또는 CPU/메모리 자원 보장은 제공하지 않으며, Windows에서 검증하지 않았습니다. Stage57 원본 요구사항은 **부분 구현·BLOCKED** 로 유지하고 개발은 Stage58로 전진합니다. Stage54 웹 조사와 Stage56 GGUF 실모델 검증도 보류입니다. 자세한 검증은 `docs/verification_stage57_restricted_ast/summary.md`에 있습니다.


### 58단계: 이미지·영상·문서 도구 연결 구조 (부분 구현)

`desktop/media_tool_adapters.py`에 고정된 7개 로컬 읽기 전용 어댑터(이미지 PNG/JPEG, 영상 MP4/WebM, 문서 TXT/MD/PDF/DOCX)의 선언적 계약과 선택형 디스패치를 추가했습니다. 관리자 로그인 및 파일 선택·별도 승인 후에만 최대 20MiB 파일의 제한된 헤더/구조 검사와 SHA-256을 수행하고, 파일 경로 대신 파일명/해시/검사 결과만 추가 전용 SQLite에 기록합니다. Tkinter의 `이미지·영상·문서 어댑터` 탭에서 선택·취소·검사·이력 확인이 가능합니다. 파일은 수정하지 않으며 네트워크·프로세스·플러그인 로딩을 하지 않습니다. 헤더 확인은 완전한 파일 디코딩 검증이 아닙니다.

**원본 58단계 전체 완료 아님**: 실제 이미지 제작·편집, 영상 제작·편집·렌더링, 문서 생성·변환을 위한 로컬 도구/모델/코덱 실행 통합은 구현하지 않았습니다. Windows 실기기 및 실제 미디어 렌더러 검증도 미완료입니다. 58단계는 BLOCKED/부분 구현으로 보존하고 다음은 59단계입니다. 완료 단계 개수는 기존 54/100개로 유지합니다. 상세: `docs/verification_stage58_media_adapters/summary.md`.
