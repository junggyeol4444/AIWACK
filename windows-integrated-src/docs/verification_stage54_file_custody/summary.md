# AIWACK Stage54 계속 개발 — 사용자가 선택한 로컬 파일 바이트 재검사

## 기준과 진행 상태

- 기준 최신 누적 소스: `AIWACK_Stage54_Offline_Source_Overlap_Continuation_Source.zip` (원본 파일 항목 550개). 모든 기존 파일을 남겼으며 기존 550개 중 544개 바이트 동일, 6개 수정; `source_preservation.txt` 참조.
- 시작 전에 누적 ZIP 내부 `docs/original_project_spec.txt`, `docs/requirements_traceability.md`, `docs/roadmap_100.csv`, `docs/roadmap_100.md`, `docs/progress.json`의 실제 내용을 확인함. 별도 독립 첨부 원본 기획서는 로컬에서 확인할 수 없어 ZIP 내부 원본을 기준으로 함.
- 원본 기획안, 요구사항 추적표, CSV 로드맵, 이전의 `dev_company.sqlite3`의 SHA-256이 원본과 동일. 원본 완료 1~53단계 유지; 54단계는 **미완료**, 55단계 미착수.

## 실제 구현

- 새 `desktop/research_file_custody.py`: **사용자가 명시적으로 선택한** 로컬 일반 파일을 읽고 저장된 `offline_research_local_imports`의 원본 바이트 해시·크기·파일명을 대조하는 읽기 전용 API. 개별 파일 가져오기와 JSON 묶음 가져오기 모두 대응.
- 선택 파일의 바이트 크기가 같은 경우에도 내용이 바뀌면 SHA-256 불일치 보고. 이름이 다르지만 내용이 같은 사본은 바이트 일치/파일명 불일치를 분리. 보관된 자료 확인, 빈 파일·잘못된 UTF-8로 변경된 자료도 불일치 확인 가능.
- 로컬 파일 경로는 SQLite에 저장하지 않으며 자동 디스크 순회·서버 연결·DNS·원격 자료 가져오기·외부 API 호출 없음. 256KB 상한, 로컬 절대 경로·일반 파일 여부·심볼릭 링크·Windows 접합점·매핑된 네트워크 드라이브 점검. 바이트 읽기 전후의 파일 크기·시간·inode 점검으로 기본적인 파일 교체 경쟁 차단(Windows 실기기 미검증).
- `desktop/storage.py`: 관리자 권한 확인 후 기존 SQLite의 등록 기록을 조회하는 API 추가. `desktop/app.py`: Tkinter **선택 자료 원본 파일 재검사** 버튼, 읽기 전용 상세 비교 화면 및 실패/불일치 표시. `scripts/verify_offline_runtime.py` 신규 GUI 회귀 검사 연결.
- 기존 저장 데이터 또는 스키마 수정·마이그레이션 없음. 과거 기획안을 변경하지 않고 새 조사 보조 기능만 추가.

## 검증

- **단일 전체 `PYTHONPATH=. python -m pytest -q` 실행: 1,064개 통과, 0개 실패, 113.61초**. 원본 1,034개에 신규 30개 포함. `full_pytest.log`, `new_tests.log`.
- 신규 테스트 30개 통과: 동일 바이트, 파일명 변경, 같은 크기/다른 크기 내용 변조, UTF-8 손상, 빈 파일, 256KB 상한, 자료 ID 입력 검증, 수동 자료 처리, 경로·심볼릭 링크 차단, 보관 자료, 관리자 인증, 재로그인, 묶음 가져오기, SQLite 바이트 불변, Python 소켓 차단.
- 기존 테스트 fixture의 JSON manifest 키를 최초에 잘못 지정하여 신규 테스트 첫 실행이 **29통과·1실패**였음. 기존 묶음 포맷에 맞게 테스트 fixture를 수정한 후 신규 30개 및 전체 1,064개가 통과. 구현상의 자동 묶음 규격은 변경하지 않음.
- Linux Xvfb Tkinter 실제 버튼 호출, 일치/변경 탐지, 재로그인 검사 통과 (`gui_smoke.log`). Python 소켓 및 DNS 차단된 실행 환경에서 **오프라인 자체 검사 및 GUI 39개 명령 모두 통과**, 전체 일괄 실행 종료 0 (`offline_runtime.log`). `python -m compileall` 통과.
- 소켓 차단은 Python 코드 계층의 테스트 가드이며 운영체제 방화벽/전체 시스템 통신 차단의 검증과는 다름.

## 해석 한계 및 진행률

- **SHA-256 일치 = 선택된 현재 사본이 등록 시 기록된 바이트 해시와 같음**. 실제 웹사이트 출처, 원본 파일의 보관 연속성, 파일의 최초 진위/서명, 문서 사실성, 독립적 출처, 데이터 수집 시점은 입증하지 않음.
- Windows 10/11 실기기, Windows EXE 빌드, 실제 GGUF 추론, 장시간 자율 운영, 디스크 파일 교체에 대한 Windows 경쟁 조건, 실제 웹 조사·자동 수집은 구현/검증하지 않음.
- 원래 54단계 '인터넷 조사 및 자료 수집'은 **외부 서버 접속 금지** 조건으로 완료할 수 없음. 로드맵 **53/100 완료(53%)**, 54 진행 중. 실질 제품 완성도 **약 20~25%**, 기능·시나리오 전체를 실제로 검증한 수치가 아닌 주관적 추정치.
