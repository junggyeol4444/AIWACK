# 65단계 — 총괄 AI의 사업 선택·실행 판단 (오프라인 부분 구현)

기준: 원본 기획안 제4장, 제11장 시나리오 A, 원본 100단계 로드맵 65번.

## 구현 범위

- 기존 64단계 금융 가정 평가(입력/결과/감사 해시 확인)를 읽어 동일 평가 기간·서로 다른 사업/후보 최대 10개를 비교한다.
- 가정상 기간 손익 순서, 하향/기준/상향 가정 금액, 손익분기 가정 수량 및 누락된 검증 조건을 보존한다.
- 비교 결과는 항상 `HOLD_NO_EXECUTION`, `chief_ai_inference_performed=false`, `external_actions_executed=false`로 기록한다. 이 순위는 사업 추천이 아니다.
- 관리자 Tkinter 화면에서 별도 확인 후 로컬 검토 기록을 생성, 확인/거부한다. 확인은 실제 실행 승인이 아니다.
- SQLite 추가 전용 검토/감사 이벤트와 이전 이벤트 해시 연결, 읽을 때 원본 금융 평가·스냅샷·감사 이력 검증.
- 기존 사업/후보 상태, 프로젝트, 외부 서비스, 매출/지출 및 실제 모델 호출은 변경하거나 실행하지 않는다.

## 미완료

실제 총괄 AI GGUF 추론과 독립적 사업 비교·선택·실행 판단, 검증된 시장·재무 근거, 실행/프로젝트 생성, Windows 실기기 검증. 원본 완료 조건은 축소하지 않았으며 65단계는 BLOCKED. 다음은 66단계.

## 검증

`logs/initial_pytest.txt`: Stage65 + Stage64 + 프로젝트 구조 pytest 64개 통과.

`logs/selected_regression_pytest.txt`: Stage55~65 + 프로젝트 구조 259개 통과.

`logs/stage65_gui.txt`: Stage65 Linux Xvfb Tkinter GUI, 관리자 인증/취소/저장/검토/로그아웃 차단, socket/DNS 차단 통과.

Stage61~65 기존 GUI 스모크 5개 통과. 단일 전체 pytest는 이번 실행에서 수행하지 않았으며 전체 회귀 성공이라고 주장하지 않는다. 이전 Stage63 병렬 subprocess 시간 임계 테스트 실패는 해결했다고 주장하지 않는다. Windows/실제 GGUF/외부 서비스/장시간 실행은 미검증.

해시 무결성은 로컬 데이터의 실수/일부 변조 감지용이며, 관리자 DB 직접 수정 권한을 가진 공격자에 대한 암호학적 위변조 방지는 보장하지 않는다.
