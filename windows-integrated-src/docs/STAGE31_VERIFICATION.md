# 31단계 검증 기록 — 회사 상황 자동 점검

기반: 실제 `AIWACK_Stage30_Local_Offline_Source.zip`을 압축 해제한 뒤 `docs/progress.json`에서 `completed_steps=1..30`, `next_step=31`을 확인했다. 로드맵의 31단계는 `회사 상황 자동 점검`이며 기존 원본 기획서와 단계 기록은 보존했다.

## 구현 범위

- 로그인된 관리자 PC의 SQLite 데이터만 조회하여 **업무 총계/상태, 담당자 없는 미완료 업무, 검수 대기 결과물, 검토 대기 총괄 보고서, 1시간 이상 미종료 실행, 최근 24시간 실패·시간초과·중단 실행**을 일관된 트랜잭션으로 집계한다.
- 정해진 코드와 건수로 `ok/attention/critical` 판정. 실제 비즈니스 기회·품질을 AI로 분석하는 기능은 아니다. 오래된 실행 기록은 프로세스 실제 생존 여부를 뜻하지 않는다.
- Tk `회사 자동 점검` 탭, 관리자 로그인 직후 자동 점검, 앱이 로그인된 채 열린 동안 **5분 간격** 점검, 수동 점검 버튼 및 최근 30건 조회. 로그아웃 시 Tk 타이머를 취소한다. 앱 종료 후 백그라운드 실행은 없다.
- `company_health_checks` 신규 SQLite 테이블은 **건수·고정 코드만 저장**한다. 자동 점검은 집계가 달라지거나 마지막 저장 후 1시간이 지난 경우에만 추가 저장한다. 수동 점검은 강제로 별도 저장한다. 직원명·업무 제목·본문·프롬프트·모델 출력은 저장하지 않는다.
- **읽기 전용 검사**: 점검으로 업무/실행/검수/직원 상태를 바꾸거나 모델을 실행·다운로드·호출하지 않는다. 네트워크 사용 없음. 기존 30단계의 관리자 승인·실행 경계를 유지한다.
