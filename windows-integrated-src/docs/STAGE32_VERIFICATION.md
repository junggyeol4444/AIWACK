# 32단계 검증 기록 — 문제 및 내부 사업 기회 후보 감지

기반: `AIWACK_Stage31_Local_Offline_Source.zip`을 실제 압축 해제하여 `docs/progress.json`의 `completed_steps=1..31`, `next_step=32`를 확인한 뒤 구현했다. 기존 파일·원본 기획·기존 단계의 기록을 보존했다.

## 구현 및 명확한 한계

- `desktop/opportunity_detector.py`: 기존 31단계의 로컬 상태 집계와 추가 SQL로 **미종료 실행·긴급 차단·일반 차단·미배정·최근 실패·검수/총괄 검토 대기**의 고정 규칙 문제 신호 7종을 감지한다. `urgent_blocked`는 긴급 우선순위가 명시적으로 지정된 차단 업무만 센다.
- **내부 기회 후보 2종**: (1) `active` 목표에 비보관 업무 계획이 없는 경우, (2) `active` 목표의 `ready` 계획에 취소되지 않은 업무가 없는 경우. 상태를 변경하면 다음 조회에 즉시 반영된다. 대상 목표/계획 ID는 화면에서 최대 20개만 표시하며 저장 이력에는 포함하지 않는다.
- 이 신호는 **이미 사용자가 입력한 목표/계획의 미진행 사항**을 찾는 결정적 규칙이다. **외부 사업 기회, 시장 수요, 경쟁, 매출 가능성, 실행 가능성, AI 아이디어 생성은 검증/구현하지 않았다.** 신호가 존재해도 업무나 계획을 만들거나 실행하지 않는다.
- `company_detection_checks`: 고정 코드·분류·수준·건수만 저장. 1시간 내 동일 결과는 자동 중복 기록하지 않으며 수동 검사에서는 새 이력을 남긴다. 관리자 인증 필요. 사용자 목표/계획 제목, 업무 내용, 모델 출력, 대상 ID는 이력에 저장하지 않는다.
- Tk `문제·사업 기회 감지` 탭은 22번째 탭. 로그인 직후 및 **로그인 상태로 앱을 열어 둔 동안** 5분 간격 검사, 수동 검사, 실시간 신호, 최근 30건 이력. 로그아웃 시 타이머 중단. 백그라운드 OS 서비스 없음.
- GitHub 접속/업로드/커밋/병합, 원격 서버, 클라우드 모델 호출 및 외부 전송을 수행하지 않았다. Python 네트워크 소켓 차단 검사는 **사용자가 지정한 로컬 실행파일에 대한 OS 수준 네트워크 격리**를 의미하지 않는다.

## 압축본 재검증

`AIWACK_Stage32_Local_Offline_Source.zip`의 134개 파일을 별도 폴더에 압축 해제하여 전체 3묶음 **103+117+119=339개 통과**를 확인했다. 두 번째 묶음의 첫 실행은 환경 시간 제한으로 중단되었지만, **압축 해제본에서 동일 코드를 다시 실행한 `pytest -vv` 결과 117개 전부 통과**했다. 압축 해제본에서 `python -m scripts.verify_offline_runtime` **통과**(자체 검사, 기존 GUI, Stage29~Stage32 GUI), `python scripts/next_step.py` **32 완료/33 다음**을 확인했다. 최종 문서 수정은 코드·테스트·진행표에 영향을 주지 않는다.

ZIP에는 사용자 SQLite 데이터베이스·비밀번호·모델·캐시·`.git`·`.github` 설정을 포함하지 않는다. Windows EXE가 아닌 **전체 누적 로컬 소스 ZIP**이다.
