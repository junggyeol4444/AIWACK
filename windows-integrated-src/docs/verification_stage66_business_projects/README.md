# 66단계 — 다중 사업과 프로젝트 관리 (오프라인 부분 구현)

기준: 원본 `docs/original_project_spec.txt` 제4.3절(사업별 운영 조직), 제11장 시나리오 A 및 100단계 로드맵 66번. 이전 65단계 누적 ZIP을 기준으로 변경했다. 원본 기획안과 T01~T20 검증 기준은 변경하지 않았다.

## 구현

- 61단계의 여러 사업에 각각 여러 개의 독립 프로젝트 계획을 연결한다. 각 프로젝트는 사업 ID, 제목, 목표, 별도 **계획 예산**, 선택적 책임 AI 직원(해당 사업 참여자만), 수동 계획 상태를 가진다.
- 관리자 수동 상태 `planned → active → paused → active/completed/cancelled` 등 유효한 전환만 저장한다. `active`는 로컬 계획 상태이며 **실제 AI 실행/지출/사업 운영이 아니다**.
- 기존 23단계 `company_tasks`의 실제 존재하는 업무 ID만 프로젝트에 수동 연결/해제한다. 같은 업무를 두 프로젝트에 중복 연결할 수 없고 업무의 실행·상태·담당자를 바꾸지 않는다.
- SQLite 외래키, 이벤트 감사 이력(추가 전용 UPDATE/DELETE 차단), 이벤트 해시 체인 및 현재 상태·업무 연결과 감사 기록의 재검사를 제공한다. 프로젝트 원본 사업/제목/목표/예산/담당자 필드는 변경 불가다.
- 관리자 인증이 필요한 Tkinter 탭을 제공하며 로그아웃 후 접근을 거부한다. 43단계 프로젝트 협업 **대화방**과 사업 프로젝트 계획은 별개의 데이터다.
- 로컬 SHA-256 해시 검사는 관리자 DB 파일 직접 조작을 막는 디지털 서명이 아니다.

## 원본 완료 조건 대비 미완료/보류

총괄 AI 자율 프로젝트 생성·실행·관리, 프로젝트별 외부 서비스 계정/고객/매출/지출/순이익, 실제 사업 성과 평가, AI 직원의 실제 프로젝트 업무 수행, Windows 실기기·EXE·실제 GGUF·외부 서비스·장시간 자율 운영 검증. 사용자 승인 없는 지출/전송/외부 접속은 수행하지 않는다. **66단계 BLOCKED; 다음 67단계 상품 및 서비스 정보 관리로 전진.**
