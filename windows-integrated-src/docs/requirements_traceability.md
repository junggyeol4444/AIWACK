## 필수 운영 원칙

- 사용자는 회사 소유자이며 최종 관리 권한을 보유한다 (원문 1.3, 8장).
- AI 회사 내부의 계획과 실제 외부 작업 실행을 구분한다 (원문 14장).
- 금전 지출, 법적 계약, 권한 변경에는 승인 절차를 두며, 비상 정지 기능은 총괄 AI 판단과 분리한다.
- 매출은 AI가 생성한 숫자가 아닌 검증 가능한 외부 결제/정산 이벤트로 판단한다.
- AI 모델 가중치 재학습과 경험·기억 기반 개선은 별개의 기능이다.
- 24시간 운영 목표는 운영 엔진이 지속 실행한다는 뜻이며 모델을 항상 추론시킨다는 뜻은 아니다.
- 초기 개발 단계에서는 외부 지출, 계정 생성, 실제 고객 정보, 실거래 실행을 활성화하지 않는다.

R07의 73단계는 Stage72 미게시 초안에 연결된 로컬 비실거래 모의 주문·수동 상태 이력만 검증합니다. 실제 외부 주문·결제·고객·매출·상품 전달은 없고 Windows 실기기 미검증입니다. 다음 개발은 원본 74단계입니다.

## Stage78~80 고객지원·재무·예산 오프라인 부분 구현 추적 (BLOCKED)

원본 R07(판매·정산·환불), R11(예산·승인), R13(관리자 UI)과 연계한 순수 모의 데이터 구조입니다.
Stage78은 가명 합성 티켓만 관리하며 실고객 데이터/연락을 수집하지 않습니다. Stage79는 모든 매출·지출·정산 참조를 미검증 가정으로만 저장합니다. Stage80은 KRW 가정 손익과 예산을 계산하며 USD/EUR/JPY는 환율 미검증으로 집계에서 분리합니다. 실거래 증빙이나 회계 적합성 보장은 없고 Windows 실기기·외부 연결은 미검증입니다. 원본 R07/T11~T13 최종 통합 검증은 유지하여 미완료입니다. 다음 단계는 원본 81단계입니다.

## Stage81~83 직원·부서·사업 기록 현황 및 비실행 개선 초안 (BLOCKED)

R08(경험·성과 기반 개선), R13(관리자 화면)에 대응하는 오프라인 기술 구조 일부입니다. Stage81은 로컬 업무 상태 건수만 표시하여 AI·직원 역량 평가를 입증하지 않습니다. Stage82는 모의 예산 경고/차단 업무·대기열만 탐지하며 실제 매출 추세는 NOT_EVALUABLE로 반환합니다. Stage83은 관리자 결정 전 무동작 초안만 저장하며 회사 업무를 생성/실행하거나 외부 네트워크에 접근하지 않습니다. 다음 원본 단계는 84입니다.

## Stage84~86 로컬 인력·모델·현황 초안 (BLOCKED)

R02(모델·직원), R08(조직 개선), R13(관리 화면)의 일부 메타데이터 부분을 다룹니다. 인력 배치와 모델 선택은 감사 가능한 초안일 뿐 실제 프로필 변경·모델 로딩/추론이 없으며, 대시보드 새로고침은 로컬 기록만 읽습니다. 실제 라이브 성과·Windows·장시간 운영/T01~T20 통합 검증은 미완료입니다. 원본 다음 87단계로 진행합니다.
