# 33단계 검증 기록 — 로컬 자동 업무 제안 및 선택적 총괄 AI 초안

기반: 실제 `AIWACK_Stage32_Local_Offline_Source.zip`의 전체 소스를 압축 해제하고 `docs/progress.json`의 `completed_steps=1..32`, `next_step=33` 및 `docs/roadmap_100.csv`의 33단계 `TODO`를 확인한 뒤 변경했다. 기존 소스·원본 기획·테스트·문서 및 사용자 데이터 구조를 보존했다.

## 구현 범위

- `desktop/autonomous_task_proposals.py`: 기존 회사 감지 로직과 일관된 **세 가지 로컬 규칙**(차단 업무, 실행 업무 없는 준비 계획, 계획 없는 활성 목표)에서 **승인 대기 업무 초안**을 자동 생성. 원본 제목·본문은 규칙 초안에 복제하지 않고 출처 유형/숫자 ID와 고정 템플릿만 사용한다. 최대 30개/스캔(1~100 설정 가능), 우선 차단 업무, 출처별 유일 제약 및 SQLite `BEGIN IMMEDIATE`로 중복/동시 스캔 방지.
- `company_task_proposals`: 초안/출처/상태/관리자 결정/연결된 실제 업무 ID/선택적 로컬 AI 출력 출처를 SQLite에 보관. 기존 테이블은 비파괴로 유지. 거절/승인/조건 변경된 출처는 같은 출처로 반복 제안하지 않는다.
- 관리자 로그인 직후 및 앱 실행 중 5분마다 초안을 스캔하고, 실제 `company_tasks` 레코드는 **관리자 명시 승인 버튼**을 눌러야만 `todo` 상태로 생성된다. 승인 시 출처 상태를 원자적으로 다시 검사하고 계획 연결·업무 상태 이력을 함께 기록한다. 담당 AI 자동 지정/모델 실행/업무 완료/외부 조치는 하지 않는다.
- `desktop/autonomous_task_ai.py`: **선택적** 총괄 AI 로컬 모델 초안 구체화. 관리자에게 총괄 AI 및 로컬 모델이 구성되어 있어야 하며 **로그인 세션마다 직접 자동 초안 기능을 켜야 한다**. 백그라운드 스레드로 한 번에 하나, 5분 주기마다 최대 한 개의 고정 규칙 초안을 JSON(`title`, `description`)으로 구체화한다. 입력을 신뢰할 수 없는 데이터로 표시하며 출력은 길이·필드 검사 후 저장. 취소·로그아웃·모델 실패 시 실행 중지. **AI 모델의 출력은 데이터일 뿐 작업 실행 명령이 아니다.**
- Tk `자동 업무 제안` 탭(23번째): 자동/수동 스캔, 제안 목록, 관리자 확인 후 승인·거절, 선택적 로컬 총괄 AI 초안 켜기/끄기, 저장 결과 확인. 기존 22개 탭 유지.
- **한계:** 기본 자동 초안은 결정적 규칙이지 AI 추론이 아니다. 선택적 로컬 모델은 관리자 동의·실행파일·모델 구성 없이는 실행하지 않는다. 실제 GGUF 모델 품질/Windows EXE는 검증하지 못했다. 지정한 로컬 실행파일이 네트워크를 사용하지 않는다는 OS 수준 보장도 없다. 모델 생성 초안과 승인된 업무 본문은 SQLite에 암호화되지 않은 평문으로 저장된다. 프로그램이 닫히면 자동 스캔/모델 작업은 수행되지 않는다.

## 오프라인 및 데이터 경계

GitHub 접속·조회·업로드·커밋·PR·병합·Actions, 원격 서버, 클라우드 AI API, 자동 결제 및 외부 거래는 사용하지 않았다. Python 소켓 차단 검사는 **선택한 로컬 실행파일의 네트워크를 OS 수준에서 차단한다는 뜻이 아니다.**

ZIP에는 기존 누적 소스·테스트·문서·100단계 로드맵을 포함하되 실제 사용자 SQLite 데이터베이스, 비밀번호, GGUF 모델, 테스트 캐시, `.git`, `.github`를 포함하지 않는다. 결과물은 Windows EXE가 아닌 로컬 소스 ZIP이다.
